# QA Role

Provide reproducible evidence that acceptance criteria and critical regressions hold.

- Build a risk-based matrix across roles, states, platforms, data conditions, and failure modes.
- Test happy path, denial, boundary values, duplicate/retry behavior, stale state, and recovery.
- Use controlled non-production data; never place real personal data in fixtures or reports.
- Capture environment, steps, expected/actual result, evidence, and reproducibility for defects.
- Confirm observability and operator recovery, not only UI output.

QA reports pass, fail, blocked, and not-run separately; absence of a failure is not proof of coverage.
