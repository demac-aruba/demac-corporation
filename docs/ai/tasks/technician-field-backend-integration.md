## Private files and recovery
Use the same authenticated `fieldOperationsAuthority` HTTP boundary:
1. `record_procedure_action` / `prepare_media` reserves an immutable per-user manifest with kind, view, byte size, SHA256, source and declared capture timestamp.
2. `POST ?procedureMedia=upload&visitId=...&interventionId=...&captureId=...`, bearer-authenticated, receives the original binary body with its declared content type. No base64 is stored in business documents. Server-authorized private Storage paths, content signature/type/size validation and `ifGenerationMatch:0` prevent replacement. An exact existing upload is a replay; different content is rejected.
3. `commit_media` authenticates before Storage reads and revalidates assignment/owner/review context transactionally. It links the actual generation/hash to exactly one fieldEvidence record and the originating step, then removes its pending reservation atomically. A partial metadata failure preserves the pending reservation and can replay without another upload.
4. `GET ?procedureMedia=read&visitId=...&interventionId=...&evidenceId=...` authorizes the current context and reads the pinned private generation with no-store/nosniff headers. No permanent public download URLs or credential-bearing URL is issued.

A safety-revision change blocks an unacknowledged delayed file link. The original author may explicitly recover the unchanged already-reserved file with a reason; this never restores a safety authorization or clears risk. Account-to-staff changes are rejected. An owner may cancel a draft reservation with a reason; office may abandon an unavailable companion reservation with reason and safety version so responsible recovery is not permanently locked. Original ownership/path remain in audit, missing required views still block, and no Storage bytes are deleted. Automated cleanup of unlinked objects and the browser binary outbox are **not delivered** by this server recovery boundary.

Limits are 12 MiB photo / 6 MiB audio / 20 MiB video; at most 60 pending reservations and a bounded workflow document. Codec container signatures are checked, not a claim of complete decoding or browser/phone format acceptance. Durations/timestamps supplied by the device remain declared data, not certified media metadata. Physical-device recording/playback remains acceptance work.
